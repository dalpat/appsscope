# AppsScope

A Linux app store that tells you what an app can actually do to your computer —
before you install it.

Plenty of Flathub apps ship `filesystems=host` — unrestricted access to every
file you own. One of the three apps installed on the machine this was developed
on does. GNOME Software reduces this to a vague "Potentially unsafe" label. KDE Discover barely mentions it. The only way to find out today is to
install the app first, then go read its permissions in a separate tool.

AppsScope makes that the centrepiece:

- **Every app shows its packaging format** — a pill on every card, list row
  and app page, so you never have to wonder whether you're about to install a
  Flatpak, a distro package, or an AppImage.
- **Every app is graded** — Sandboxed, Limited access, or Full access — in
  plain language, with the consequence spelled out rather than the flag.
- **The Installed list badges every app**, so an app that can read your whole
  home directory is obvious at a glance.
- **The install dialog says what you're actually getting** — the packaging
  format, the source, the real download size, and every extra package that
  comes with it. KolourPaint is a 1.3 MB app; installing it on a machine
  without the KDE runtime downloads **791 MB** and uses **2.7 GB** on disk.
  AppsScope resolves that against your machine and says so before you commit.
- **Installing shows a consent dialog** listing exactly what you're granting.
  A confined app gets a short, calm dialog; an unconfined one gets a loud
  one — so the loud version still means something.
- **Permissions are revocable in place.** Flip a switch to take away host
  filesystem access. It writes the same override file `flatpak override` and
  Flatseal use, so the change is visible to both.

## Install

Download the `.deb` and install it — apt pulls in the libraries:

```sh
sudo apt install ./appsscope_0.1.0_amd64.deb
```

Then launch **AppsScope** from your applications menu, or run `appsscope`.

Requires libadwaita 1.6+ and GTK 4.12+, which means Ubuntu 24.10+, Debian 13+,
or Fedora 40+. **Ubuntu 24.04 LTS ships libadwaita 1.5 and is not supported** —
`AdwSpinner` is what sets that floor.

`flatpak` and `packagekit` are Recommends, not Depends: either can be absent
and that backend simply won't appear. Both are installed by default on Ubuntu
and Fedora workstation.

To remove: `sudo apt remove appsscope`

### Other distributions

There's no rpm or AUR package yet. Build from source:

```sh
sudo apt install libgtk-4-dev libadwaita-1-dev libflatpak-dev build-essential
cargo build --release -p appsscope-gtk
```

Not shipped as a Flatpak, and deliberately so: AppsScope has to reach host
Flatpak installations and the system PackageKit daemon, which from inside a
sandbox needs `--talk-name=org.freedesktop.Flatpak` plus host filesystem
access — the two permissions this app's own permissions panel grades as
*Critical, defeats the sandbox*. Shipping that would contradict the entire
point of the app. It's the same reason GNOME Software isn't distributed as a
Flatpak.

## Build

Requires Rust 1.85+ (edition 2024) and GTK development headers:

```sh
sudo apt install libgtk-4-dev libadwaita-1-dev libflatpak-dev build-essential
cargo run -p appsscope-gtk
```

To build the package:

```sh
cargo build --release -p appsscope-gtk
packaging/build-deb.sh          # writes dist/appsscope_<version>_<arch>.deb
```

The dependency line is generated by `dpkg-shlibdeps` from the binary's symbol
versions rather than hand-written, so it stays correct as the code changes.

First launch parses Flathub's 48 MB AppStream catalog and takes ~30 s; after
that it's skipped unless the catalog changes, and startup is instant.

If Explore is empty, there's no AppStream data on disk yet:

```sh
flatpak update --appstream
```

## Layout

| Crate | Purpose |
|---|---|
| `appsscope-core` | `Backend` trait and domain types. No GTK, no I/O. |
| `appsscope-catalog` | AppStream → SQLite + FTS5. Search and browse queries. |
| `appsscope-flatpak` | Flatpak backend over libflatpak. |
| `appsscope-gtk` | GTK4 + libadwaita frontend, built on relm4. |

| `appsscope-pk` | Distro packages over PackageKit's D-Bus API. |

Planned: `appsscope-appimage`.

## Design notes

**"Install" is not one thing, so the dialog says what it is.** A 1.3 MB app can
pull an 800 MB runtime; the same app may exist as a Flatpak and a snap with
completely different confinement. The install plan is resolved by building the
real transaction, letting Flatpak resolve dependencies against what's already
on the machine, capturing the operation list, and aborting from the `ready`
signal before a byte is downloaded. Items already installed never appear, so
the figure shown is what will genuinely be fetched.

**GTK's CSS is a subset, and it fails silently.** A bad rule is skipped and the
UI is subtly wrong with no warning — notably `@media (prefers-color-scheme:)`
is tolerated but not honoured, so hand-picked light/dark colour pairs are wrong
in one theme with nothing to tell you. `ui::style` connects to `parsing-error`
and logs every failure with its location, and all colours come from libadwaita's
named palette so they adapt on their own.

**Permissions are the product; the catalog is what makes it usable.**
A store that browses well but hides what it installs is the status quo. The
grading rules live in `appsscope-flatpak/src/sandbox.rs` and are deliberately
opinionated: the worst cases — whole-filesystem access, raw bus access, an app
that can drive Flatpak itself — cannot hide behind a wall of harmless
capabilities, because the overall grade is the *worst* permission, never an
average. Permissions we don't recognise are shown verbatim rather than dropped;
silently hiding one would be the single unforgivable bug in this feature.

**The home page leads with artwork.** A featured carousel uses each app's own
screenshot as full-bleed background under a gradient scrim, with the icon, name
and summary over it. This is the single biggest difference between a storefront
and a package list — without artwork a home page is a directory. Screenshots are
downscaled to 1600px wide at fetch time on a blocking thread: Flathub serves
originals, some over 4000px, and decoding 14 megapixels on the GTK main thread
stutters the carousel every time a card scrolls in.

**Every icon sits in a rounded plate.** Flatpak icons are a mix of full-bleed
artwork and transparent logos at wildly different visual weights, so drawing
them raw gives a ragged row. `GTK_OVERFLOW_HIDDEN` plus a CSS `border-radius`
gives true rounded clipping, so full-bleed art is cut to the rounded square
rather than overflowing. It's most of the difference between "list of images"
and "shelf of apps".

**One navigation system, not two.** Every destination — Home, Installed,
Updates, and all nine categories — lives in a single sidebar. Categories were
previously a horizontal chip strip that hid most of itself off the right edge,
and splitting destinations between a sidebar and a top switcher would mean
memorising which kind of thing lives where. An `AdwBreakpoint` collapses the
sidebar to an overlay below 860sp, and choosing a destination dismisses it.

Search sits in the header rather than inside one view, and takes precedence
over the sidebar selection while it has text — typing is a stronger signal of
intent than the last thing clicked. Navigating clears it, so picking "Games"
mid-search doesn't silently appear to do nothing.

**Explore is shelves, not a grid.** A uniform grid of alphabetically-ordered
apps gives no reason to look at any one of them. Horizontal shelves — Recently
updated, Games, Graphics & Design — impose an editorial shape, the way the Play
Store does. The grid is still there, but for search results and category
filters, where a ranked uniform list is what you actually want.

Shelves are ordered by most-recent release rather than alphabetically. There is
no popularity data available, but recency at least surfaces maintained software;
alphabetical order opened every shelf with "0 A.D." and "4KTUBE". Releases dated
in the future are excluded — a meaningful number of AppStream files carry
timestamps months ahead, and without that filter those broken entries
permanently occupied the top shelf.

**The catalog is what makes it fast.** An app store is a search frontend over AppStream
metadata with a transaction layer attached. GNOME Software feels slow because of
how it loads and merges that catalog. AppsScope parses it once into SQLite with
an FTS5 index, fingerprinted against the Flatpak commit hash, and queries that —
search over 3264 apps runs in well under a millisecond.

**libflatpak is `!Send`, so it gets its own thread.** Every libflatpak type is a
GObject that cannot cross a thread boundary. `appsscope-flatpak` runs one
dedicated worker thread that owns all of it and exchanges only plain owned data
over channels. `Transaction::run()` blocks, so this also keeps it off the GTK
main thread.

**Backends are streams, not futures.** `install`/`remove`/`update` return
`Stream<Progress>` because they're long, multi-phase, and cancellable. Dropping
the stream closes the channel, which the Flatpak worker treats as a cancel.

**Progress is allowed to say "I don't know".** `Progress.fraction` is an
`Option`. Flatpak reports real byte counts; PackageKit's percentages are often
garbage. Modelling the unknown explicitly means the UI can avoid inventing a
number, because a store that lies about progress loses trust everywhere else.

**Styling uses named colours, never hex.** The stylesheet is written against
libadwaita's `@card_bg_color` / `@accent_bg_color` and friends, so the app tracks
light/dark and the user's accent colour for free. Hardcoded colours are the
fastest way to look foreign on a GNOME desktop.

**AppStream text is untrusted.** Names and summaries come from a third-party
catalog, so markup parsing is switched off on every widget that renders them —
one unescaped `&` in an app name is otherwise enough to blank a row.

## Known gaps

- Distro packages appear under Installed and Updates, but **not in Explore**:
  browsing needs the distro's AppStream catalog, which is DEP-11 **YAML**, and
  the `appstream` crate reads XML only. That ingest path still has to be
  written before system packages are discoverable rather than just manageable.
- PackageKit refuses method calls on a transaction from any connection other
  than the one that created it, so `appsscope-pk` caches a single system-bus
  connection for the process. Opening one per call fails with
  `RefusedByPolicy: sender does not match`.
- `libadwaita` is pinned to feature `v1_7`, which excludes Ubuntu 24.04 LTS
  (ships 1.5). Lowering it costs `ToolbarView` and little else.
- Screenshots are fetched on demand and cached in
  `~/.cache/appsscope/images`, but the cache is never evicted — it grows without
  bound as you browse.
- Permission grades are only shown in the browse grid for apps you already have
  installed. For anything else the metadata needs a network round trip, so the
  grade appears on the app's page rather than on its card.
- Revoking a permission takes effect the next time the app starts, not
  immediately — that's a Flatpak constraint, and the UI says so.
